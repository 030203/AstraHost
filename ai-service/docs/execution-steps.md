# 分阶段执行步骤

## 1. 推进方式

开发节奏采用“小步、可验证、可回滚”。

每个开发步骤都必须包含：

- 目标。
- 涉及文件。
- 实现范围。
- 验证方式。
- 开发日志记录。

## 2. 阶段 0：治理和文档

目标：建立开发秩序，不修改业务代码。

任务：

- 创建 `dev-logs` 日志目录。
- 创建每日开发日志模板。
- 创建 `AGENTS.md` 项目工作指引。
- 创建 `docs` 标准文档。
- 创建 `tools/dev_log.py` 日志脚本。

验收：

- 文档路径清晰。
- 当天日志存在。
- 日志脚本可创建和更新日志。

## 3. 阶段 1：安全底座

目标：降低误调用和越权风险。

建议拆成以下小任务：

1. fallback 工具收敛。
   - 修改 `SkillService.resolve()`。
   - 未命中时只开放低风险工具。
   - 增加测试。

2. action 工具二次确认设计。
   - 新增 pending action 数据结构。
   - 先实现内存版本。
   - 暂不接 Redis。

3. action 工具执行保护。
   - `ToolService.execute()` 对 `mode="action"` 做确认校验。
   - 执行前重新读取资源状态。

4. 权限测试。
   - 覆盖 USER、MERCHANT、ADMIN、匿名用户。

验收：

- 用户咨询动作时不直接执行。
- 未登录用户不能调用身份绑定工具。
- 伪造角色不能通过生产身份检查。

## 4. 阶段 2：会话能力

目标：让 `conversationId` 真正生效。

小任务：

1. 新增 `ConversationStore` 内存实现。
2. 在 `/chat` 和 `/chat/stream` 中读取和写入会话。
3. 保存最近 N 轮消息。
4. 工具结果保存摘要，不保存完整大对象。
5. 增加 TTL。

验收：

- 用户可以追问“刚才那个订单”。
- 会话过期后不会使用旧上下文。
- 日志中能看到 conversationId。

## 5. 阶段 3：错误和观测

目标：让问题可定位、错误可解释。

小任务：

1. 定义结构化错误类型。
2. 改造 `BackendAPIService` 错误包装。
3. 改造 `ToolService.execute()` 错误返回。
4. 增加结构化日志。
5. 记录工具耗时和模型 stop reason。

验收：

- 后端 404、403、500、timeout 能生成不同错误类型。
- 客服回复不会暴露内部异常。
- requestId 能串起一次完整请求。

## 6. 阶段 4：流式体验

目标：实现真正模型流式输出。

小任务：

1. `AnthropicClient` 增加 stream 方法。
2. `ChatService.stream_chat()` 改为真正 SSE 事件。
3. 增加 `tool_start`、`tool_result`、`chunk`、`done` 事件。
4. 前端展示工具调用状态。

验收：

- 首字响应快于非流式接口。
- 工具调用时前端有查询状态。
- 错误事件能正确展示。

## 7. 阶段 5：意图路由升级

目标：减少关键词漏判。

小任务：

1. 保留关键词规则。
2. 增加业务编号格式识别。
3. 当规则低置信时调用模型分类。
4. 分类输出固定 JSON。
5. 增加路由行为测试。

验收：

- “这笔钱扣了吗”能路由到支付。
- “明天到店怎么拿钥匙”能识别为入住/订单相关咨询或追问。
- 低置信场景不会暴露敏感工具。

## 8. 阶段 6：生产化收尾

目标：进入真实客服环境前的收口。

小任务：

- 接入正式认证。
- 会话存储从 memory 切 Redis。
- prompt 文件化。
- 增加 FAQ/RAG 方案评估。
- 建立灰度开关。
- 整理上线检查清单。

验收：

- 生产身份不可伪造。
- 多实例部署会话一致。
- 关键行为有测试和日志。

## 9. 每日执行要求

每天开发开始：

```bash
python tools/dev_log.py
python tools/dev_log.py todo --todo "今天准备完成的事项"
```

每天开发结束：

```bash
python tools/dev_log.py done --done "今天完成的事项"
python tools/dev_log.py todo --todo "下一步待办"
python tools/dev_log.py verify --verify "今天的验证结果"
```

如果当天没有代码变更，也要记录文档、讨论、设计决策或阻塞原因。
